Benchmarks

These benchmarks compare aweXpect's happy-path overhead (passing assertions, the dominant case in a healthy test suite) against the equivalent FluentAssertions and TUnit calls.

Methodology
  • Suite: HappyCaseBenchmarks driven by BenchmarkDotNet.
  • Job: MediumRun with the in-process toolchain.
  • Runner: ubuntu-latest GitHub Actions agent, refreshed on every push to main.
  • Each tab shows the latest measured time and allocated memory; bars are scaled within the row so length corresponds to magnitude. Lower is better.

Verifies that an event was raised, including starting the recording and raising the event. TUnit has no event recording to compare against, so it is not part of this benchmark. FluentAssertions' Monitor() emits a handler for each event of the object at runtime, which is where most of its time goes.

Time
aweXpect561.8 ns
FluentAssertions51.43 µs+9055%
Memory
aweXpect1.80 KiB
FluentAssertions5.13 KiB+186%
Captured on commit ad09d2ca (2026-10-11) on ubuntu-latest.
aweXpect
using aweXpect.Recording;

Player player = new();
IEventRecording<Player> recording = player.Record().Events();
player.Play();
await Expect.That(recording).Triggered(nameof(Player.Started));
FluentAssertions
Player player = new();
using IMonitor<Player> monitor = player.Monitor();
player.Play();
monitor.Should().Raise(nameof(Player.Started));

Filters and expectations

A filter (.WhichAre… / .With…) narrows a collection before you verify it. An expectation (Expect.That(…).Is… / .Are… / .Has… / .Have…) states the rule the subject must satisfy. They mirror each other: a filter has an Is…/Are… expectation counterpart for the same concept.

How to read the tables​

The tables on the pages of this group pair them up. The Filter column is used on a selection (In.… or Types.…); the Expect (single) column applies to one subject; the Expect (many) column applies to a collection. The Negated column lists the negations in the same order (filter, single, many), leaving out a form that has none. An empty cell means that there is no such form, e.g. no negation.

Combining filters​

Filters chain naturally (each narrows the previous result). Several filters offer an Or… companion to widen a single step. The attribute expectations have one as well: OrHas<TAttribute>() on a single subject and OrHave<TAttribute>() on a collection, both also with a predicate on the attribute:

// Any of several attributes
In.AllLoadedAssemblies().Methods()
    .With<FactAttribute>().OrWith<TheoryAttribute>()
await Expect.That(method).Has<FactAttribute>().OrHas<TheoryAttribute>();
await Expect.That(methods).Have<FactAttribute>().OrHave<TheoryAttribute>(a => a.Skip == null);

// Any of several return types
In.AllLoadedAssemblies().Methods()
    .WhichReturn<Task>().OrReturn<ValueTask>()

// Any of several property/field types
In.AllLoadedAssemblies().Properties()
    .WhichAreOfType<string>().OrOfType<Guid>()

Custom predicates​

When no filter or expectation covers your rule, pass your own predicate. Like the other filters, they are available on every selection (assemblies, types and members):

FilterExpect (single)Expect (many)Negated
custom predicate.Which(x => …).Satisfies(x => …).All().Satisfy(x => …) / .Any().Satisfy(x => …)Except(x => …), Except<T>() (types only)

The custom .Which(…) filter has a universal expectation counterpart that works for every subject kind (types, members and assemblies): use aweXpect's .Satisfies(…) on a single subject and .All().Satisfy(…) (or .Any().Satisfy(…)) on a collection. See Collections and quantifiers.

The custom .Except(…) filter is the inverse of .Which(…): it removes the items that match the predicate. This is handy for defining exemptions to a rule (e.g. all async methods except this one). For types there is also a typed .Except<T>() overload that excludes exactly the type T.

// Methods with a single parameter, except the event handlers
In.AllLoadedAssemblies().Methods()
    .Which(method => method.GetParameters().Length == 1)
    .Except(method => method.Name.StartsWith("On"))

// All types of the album assembly, except one legacy type
In.AssemblyContaining<Album>().Types().Except<LegacyImportService>()

Collections and quantifiers​

Every expectation works with both a single item and a collection. A collection can be an array, any IEnumerable<T?> or, on .NET 8 and later, an IAsyncEnumerable<T?>. The plural expectations already require every item to match; for ad-hoc predicates use aweXpect's Satisfies(…) (single subject) and All() / Any() quantifiers with Satisfy(…) (collections), and combine selections with LINQ:

// The plural expectation already means "every item":
await Expect.That(types).ArePublic();

// Ad-hoc predicate on a single subject:
await Expect.That(type).Satisfies(type => type.IsSealed);

// Ad-hoc predicate across the whole collection:
await Expect.That(types).All().Satisfy(type => type.IsSealed);
await Expect.That(types).Any().Satisfy(type => type.IsAbstract);

// Mix with LINQ (assign to IEnumerable<Type?> so Where binds to LINQ):
IEnumerable<Type?> publicClasses = In.AllLoadedAssemblies().Types()
    .WhichAreClasses().WhichArePublic();
var managers = publicClasses.Where(type => type!.GetInterfaces().Length > 2);
await Expect.That(managers).HaveName("Manager").AsSuffix();

The plural expectations that only check a condition on each item, like AreSealed(), AreNotStatic(), HaveADefaultConstructor() or HaveNamespace(…), read the whole collection and list every item that violates them. They also follow aweXpect's quantifiers, which only read the items until the outcome is determined, and keep their string options:

await Expect.That(types).AtLeast(2).AreSealed();
await Expect.That(methods).AtMost(1).AreAsync();
await Expect.That(types).AtLeast(2).HaveNamespace("MusicStore").AsPrefix();

The same holds for the relations, operators, generic arguments and members of types: InheritFrom, Implement, AreGeneric, HaveOperator, HaveImplicitConversionOperator, HaveExplicitConversionOperator, OnlyHaveNullableMembers, OnlyHaveNonNullableMembers and the Contain… checks. They keep their options, like Directly(), and their negations mean that no item matches (none inherit from MediaItem):

await Expect.That(types).AtLeast(2).InheritFrom<MediaItem>().Directly();
await Expect.That(types).None().Implement<IDisposable>();
await Expect.That(types).AtMost(1).ContainMethods(methods => methods.With<ObsoleteAttribute>());

The parameter and return type expectations of methods and constructors take quantifiers as well: HaveParameter, HaveParameterExactly and their ref / out / in / params / optional variants, HaveParameterCount, HaveNoParameters, Return, ReturnExactly, ReturnVoid and AreGeneric on methods. Their options, like AtIndex(…) or OrReturn<T>(), apply to each item, and their negations, like DoNotHaveParameter<bool>(), read none have parameter of type bool:

await Expect.That(methods).AtLeast(2).HaveParameter<CancellationToken>().AtIndexFromEnd(0);
await Expect.That(methods).None().Return<Task>().OrReturn<ValueTask>();
await Expect.That(constructors).AtMost(1).HaveNoParameters();

The attribute expectations Have<TAttribute>() on types, members and assemblies and the type expectations AreOfType<T>() and AreOfExactType<T>() on properties, fields and events take quantifiers as well and keep OrHave…, OrOfType… and Directly(). Their negations DoNotHave<TAttribute>(), AreNotOfType<T>() and AreNotOfExactType<T>() mean that no item matches (none have ObsoleteAttribute):

await Expect.That(methods).AtLeast(1).Have<FactAttribute>().OrHave<TheoryAttribute>();
await Expect.That(properties).None().AreOfType<DateTime>();

On a struct collection, such as an ImmutableArray<Type>, pass the type as an argument after a quantifier, e.g. AtLeast(2).InheritFrom(typeof(MediaItem)), as C# cannot infer the collection type next to an explicit type argument.

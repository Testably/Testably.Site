aweXpect.Snapshots

aweXpect.Snapshots compares strings and objects with reviewed snapshots, which are stored next to the tests or in a store of your own, e.g. to verify generated text or a complex result without writing out the expected value.

Installation​

dotnet add package aweXpect.Snapshots
  • aweXpect.Snapshots: MatchesSnapshot for strings, objects, binary data and files. The other two packages bring it with them.
  • aweXpect.Snapshots.DiffEngine: add it to open a diff tool for a missing or different snapshot when the tests run locally; it registers itself, see Diff tools.
  • aweXpect.Snapshots.PublicApi: add it to verify the public API of an assembly with MatchesPublicApiSnapshot, see Public API.

The packages bring Expect.That with them, but not the expectations for strings, numbers or collections, so reference aweXpect as well. MatchesSnapshot and MatchesPublicApiSnapshot live in the namespace aweXpect; OrphanedSnapshots, SnapshotAcceptance, SnapshotRule and the customization need using aweXpect.Snapshots;.

At a glance​

// compare a string with the snapshot that is stored next to the test
await Expect.That(description).MatchesSnapshot();

// compare an object, written completely and indented by the aweXpect formatter
await Expect.That(album).MatchesSnapshot();

// compare an exception member-wise, without members that vary per build or machine, like the stack trace
await Expect.That(() => player.Play(album, -1)).Throws<ArgumentOutOfRangeException>().Which.MatchesSnapshot();

// replace values that change from run to run before comparing
await Expect.That(playlist).MatchesSnapshot().For.Text(@"plays=\d+").AsRegex().Mask("plays=<count>");

// replace every Guid and ISO 8601 date with a numbered placeholder ({Guid_1}, {Date_1}, …)
await Expect.That(playlist).MatchesSnapshot().For.Guids().Mask().For.Dates().Mask();

// leave out, mask or convert members of an object, selected by their name, type or declaring type
await Expect.That(album).MatchesSnapshot()
    .For.Members().WithName("PlayCount").Ignore()
    .For.Members().WithName("Id").Mask()
    .For.Members().DeclaredIn<Album>().WithName("Released").OfType<DateTime>().Convert(date => date.Year);

// store a JSON string as AlbumTests.Describes.awexpect-snapshot.json for syntax highlighting
await Expect.That(json).MatchesSnapshot().WithExtension("json");

// keep a snapshot per target framework and operating system
// (AlbumTests.Describes@net8.0@windows.awexpect-snapshot.txt)
await Expect.That(exception.Message).MatchesSnapshot()
    .UniqueFor.TargetFramework().UniqueFor.OperatingSystem();

// verify the public API of an assembly, written as C# declarations
// (package aweXpect.Snapshots.PublicApi)
await Expect.That(typeof(Album).Assembly).MatchesPublicApiSnapshot()
    .UniqueFor.TargetFramework();

The snapshot is stored as <TestFile>.<Method>.awexpect-snapshot.txt next to the test file, where <TestFile> is the name of the test file without its extension. A missing or different snapshot fails the test and writes the actual value to <TestFile>.<Method>.awexpect-snapshot.pending.txt; rename it to <TestFile>.<Method>.awexpect-snapshot.txt to accept it, or set the environment variable AWEXPECT_ACCEPT_SNAPSHOTS to all to accept all changed snapshots of a test run (or to new to only add the missing ones).

Overview​

Expectations for string and any other object:

ExpectationNegatedSummary
MatchesSnapshota string matches the snapshot stored next to the test, with rules for its lines and text
MatchesSnapshotan object matches its snapshot, written by aweXpect, with rules for its members and text

Expectations for Assembly and FileInfo, from aweXpect.Snapshots.PublicApi:

ExpectationNegatedSummary
MatchesPublicApiSnapshotthe public API of the assembly, or of the assembly in the file, matches the snapshot

Customization​

Set a value under Customize.aweXpect.Snapshots() for the current async flow, or under Customize.aweXpect.Global.Snapshots() for all tests.

ValueDefaultSummary
Acceptancenull, left to the variable AWEXPECT_ACCEPT_SNAPSHOTSwhich missing or changed snapshots are accepted
Rulesnonethe rules to mask or ignore values in every snapshot
Storea file next to the test filewhere the snapshots are kept
Comparersnonedecide whether a value matches its snapshot, e.g. for images
Reportersnoneare told about every missing, different or matching snapshot
NamedAfterTestArgumentsfalsenames each snapshot after the arguments of the test case
AttachPendingFilesfalseattaches the pending file of a mismatch to the test result

Documentation​

The full documentation is available at docs.testably.org:

  • Matching snapshots: strings, objects, exceptions, binary data and files, the file extension, encoding and line breaks
  • Accepting snapshots: reviewing the pending file, accepting all changes of a run and attaching the pending files on a build server
  • Diff tools: open a diff tool for a missing or different snapshot with DiffEngine, in which the change can be taken over into the snapshot
  • Naming snapshots: a snapshot per test case or environment, and nested under their test file in Rider and Visual Studio
  • Masking and ignoring values: mask, convert or leave out values that change from run to run
  • Orphaned snapshots: OrphanedSnapshots.CheckAsync() in the teardown of the test run reports the snapshots that no test uses any more on a build server, and deletes them while accepting all changes
  • Public API: MatchesPublicApiSnapshot from aweXpect.Snapshots.PublicApi
  • Advanced:
    • Storing snapshots elsewhere: a SnapshotStore instead of files next to the tests, e.g. a shared folder or a database
    • Comparers: decide whether a value matches its snapshot instead of the built-in comparison, e.g. an image comparer that tolerates small differences of single pixels
    • Reporters: are told about every missing, different or matching snapshot, e.g. to open a diff tool
    • Deterministic builds: how the snapshots are found when the build replaces the path of the repository with /_/

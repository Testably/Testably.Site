Masking values

Values that change from run to run, such as ids or timestamps, can be replaced with a placeholder before the subject is compared, so that the snapshot stays stable:

await Expect.That(json).MatchesSnapshot()
    .Masking.Text(album.Id.ToString(), "<album-id>");

.Masking.Text(…) replaces literal text. .Masking.Regex(…) takes a regex pattern instead, and the replacement can use the substitutions of Regex.Replace, e.g. $1 for the first group, to keep part of the match ($$ inserts a $):

await Expect.That(log).MatchesSnapshot()
    .Masking.Regex(@"(\w+\.fm):\d+", "$1:<port>");   // "radio.fm:8000" → "radio.fm:<port>"

A pattern passed as a string, and the built-in maskings below, use the regex timeout of aweXpect, Customize.aweXpect.Settings().DefaultRegexTimeout (one second by default). Options can be set inline, e.g. (?i); for a timeout of its own, pass a Regex instead: .Masking.Regex(new Regex(@"token=\w+", RegexOptions.IgnoreCase, TimeSpan.FromSeconds(5)), "token=<token>"). A pattern that times out fails the expectation, and an invalid pattern throws an ArgumentException where it is written.

The maskings are applied in the order in which they are written, so put a specific masking before a general one:

await Expect.That(playlist).MatchesSnapshot()
    .Masking.Text(DateTime.Today.ToString("yyyy-MM-dd", CultureInfo.InvariantCulture), "<today>")
    .Masking.Regex(@"\d{4}-\d{2}-\d{2}", "<date>");

In the other order, the general masking would already have replaced today's date with <date>.

The snapshot, the pending and the accepted snapshot and the failure contain the masked value, as it is what is compared. Two values that only differ in a masked part count as the same value for the check of named snapshots.

Guids and dates​

.Masking.Guids() and .Masking.Dates() replace every Guid and date with a numbered placeholder in braces, so that it stands out from the surrounding text. The same value keeps the same number, so relations stay visible in the snapshot:

await Expect.That(log).MatchesSnapshot().Masking.Guids().Masking.Dates();
Snapshot
album {Guid_1} added {Date_1} by {Guid_2}
album {Guid_1} played {Date_2}
  • A Guid is matched in the format "D" (3f2504e0-4f89-11d3-9a0c-0305e82c3301) in upper or lower case, also inside braces or parentheses, which are kept. The format "N" without hyphens is not matched, as it cannot be told apart from a hash.
  • A date is matched in ISO 8601: a date (2026-10-17) or a date with a time (2026-10-17T09:30), with optional seconds, a fraction of up to seven digits and an offset or Z. This covers how DateTime, DateTimeOffset and DateOnly write themselves with the round-trip format "o", which the aweXpect formatter uses. Culture-specific formats, a space instead of the T and a time on its own are not matched; mask them with a regex.

The numbers are counted per subject in the order of appearance, and only after the maskings that come before, so .Masking.Text(album.Id.ToString(), "<album-id>").Masking.Guids() numbers only the other Guids.

Lines of a string​

Lines that are only noise, such as durations, timestamps or banners, can be left out of a string snapshot:

await Expect.That(log).MatchesSnapshot()
    .Ignoring.LinesContaining("elapsed").IgnoringCase()
    .Ignoring.LinesContaining("Track ?: *Live*").AsWildcard()
    .Ignoring.LinesContaining(@"^\d{2}:\d{2} ").AsRegex()
    .Ignoring.Lines(line => line.Length == 0)
    .Masking.Guids();
  • .Ignoring.LinesContaining(text) leaves out each line that contains the text anywhere, compared ordinally like aweXpect's Contains. .IgnoringCase(), .AsWildcard() and .AsRegex() directly after it apply to this line rule only, not to the comparison with the snapshot. A pattern uses the regex timeout of aweXpect; a pattern that times out fails the expectation, and an invalid pattern throws an ArgumentException when the expectation is evaluated.
  • .Ignoring.Lines(predicate) leaves out each line for which the predicate returns true.
  • A line ends with \r\n, \n or \r and is checked without it. A removed line takes its line break with it, and removing the last line also removes the line break before it; the other lines keep their newline style.
  • The lines are removed before the maskings, so they don't use up numbered placeholders like {Guid_1}.

An object is written by the formatter, so a line rule on any other subject than a string throws an InvalidOperationException; leave out its members instead.

Paths, machine and user name​

Paths of the environment differ between machines, so they are masked by default:

// value                                               // snapshot
Loaded C:\Music\Discography\Tests\albums.json          Loaded {ProjectDirectory}\albums.json
Cache: C:\Users\paul\AppData\Local\Temp\abbey.tmp      Cache: {TempPath}\abbey.tmp
PlaceholderPath
{ProjectDirectory}the directory of the test project that contains the test file
{SourceRoot}the source root, see deterministic builds
{OutputDirectory}AppContext.BaseDirectory
{TempPath}Path.GetTempPath()
{UserProfile}Environment.GetFolderPath(Environment.SpecialFolder.UserProfile), on every system
  • The longest path is masked first, as they are nested in each other, e.g. the output directory in the project directory in the source root.
  • On Windows, a path matches with \ or / as separator, also with escaped backslashes (C:\\Music), as in JSON or in a string of a snapshot of an object; elsewhere only with /, as a backslash is part of a file name there. The rest of the path keeps its separators.
  • Only whole segments match, so C:\Music\Album does not match inside C:\Music\Albums.
  • The case is ignored on Windows and macOS, but not on Linux.
  • A root of the file system, such as C:\ or /, is never masked.

The paths are masked before all other maskings of the text, so these see the placeholders. Turn it off for one expectation with .Masking.Paths(false), or for all snapshots with Customize.aweXpect.Snapshots().MaskPaths.Set(false); the expectation overrides the setting in both directions.

The name of the machine and of the user are only masked when asked for, as whole words, with {MachineName} and {UserName}. The machine name ignores the case, the user name only on Windows and macOS. They are masked right after the paths, also from the setting for all snapshots, so a path in the user profile becomes {UserProfile}:

await Expect.That(log).MatchesSnapshot().Masking.MachineName().Masking.UserName();

Customize.aweXpect.Global.Snapshots().Maskings.Set([
    SnapshotMasking.MachineName(),
    SnapshotMasking.UserName(),
]);

Members and types of an object​

In a snapshot of an object, members can be left out or masked by their name or their type, while the object is written, so that they don't depend on the written text:

await Expect.That(album).MatchesSnapshot()
    .Ignoring.Member("PlayCount")                     // left out with its name
    .Ignoring.Member<DateTime>()                      // every DateTime member left out
    .Masking.Member("Id")                             // numbered: Id = {Id_1}
    .Masking.Member("Artist.StreamToken", "{token}")  // fixed replacement
    .Masking.Type<Guid>();                            // numbered: {Guid_1}
Snapshot
Album {
  Artist = Artist {
    CatalogId = {Guid_1},
    Id = {Id_1},
    StreamToken = {token}
  },
  CatalogId = {Guid_2},
  Id = {Id_2},
  Title = "Abbey Road"
}
  • A member name matches whole segments of the member path, ignoring the case, at any depth, like an ignored member of an equivalency comparison: Id matches Id, Artist.Id and Tracks[0].Id, but not TrackId; Artist.Id only matches the Id of an Artist.
  • A type matches the declared or the runtime type of a value, including Nullable<T> and derived types: .Ignoring.Member<DateTime>() also leaves out a DateTime? member and a DateTime in an object member.
  • .Ignoring.Member<T>() only leaves out members: the items of a collection, the values of a dictionary and the items of a tuple are kept, so that a List<DateTime> is not written as an empty list. .Masking.Type<T>() masks every value of the type, also these items, so use it for them, or leave out a single item by its path, e.g. .Ignoring.Member("Releases[0]").
  • A numbered placeholder is named after the last segment of the member name or after the type, and shares its numbers with the other maskings of that name, e.g. .Masking.Type<Guid>() with .Masking.Guids(). A null value is not masked.
  • Ignoring wins over masking, the first masking that matches a value replaces it, and the rules of the expectation come before those for all snapshots. They apply before the maskings of the text.

Members of a type and predicates​

A member name matches every member of that name, whichever object it belongs to. To select the member of one type only, pass an expression to MemberOf<T>(…), or decide for each value with a predicate:

await Expect.That(album).MatchesSnapshot()
    .Ignoring.MemberOf<Album>(a => a.Price)                         // only the price of an album, not of its tracks
    .Masking.MemberOf<Track>(t => t.Id)                             // numbered: Id = {Id_1}
    .Ignoring.Member(value => value.Name.EndsWith("Url", StringComparison.Ordinal))
    .Masking.Member(value => value.DeclaringType == typeof(Track) && value.Name == "Duration");
Snapshot
Album {
  Title = "Let It Be",
  Tracks = [
    Track {
      Duration = {Duration_1},
      Id = {Id_1},
      Price = 1.29,
      Title = "Get Back"
    }
  ]
}
  • MemberOf<T>(…) matches the member in an object of the type T or of a derived type. The expression must access a field or property of its parameter itself, e.g. a => a.Price; it is only read, never compiled, so it works under Native AOT. A nested member (a => a.Artist.Name) throws an ArgumentException, as the formatter does not tell the type of the object that contains the artist; select it by the type that declares it instead: MemberOf<Artist>(a => a.Name). Other expressions, e.g. a => a.ToString(), throw an ArgumentException as well.
  • A predicate gets each member, tuple item and collection item as a FormattedValue, with its Kind, Name, Path, declared Type and DeclaringType; the value itself is only read when the predicate calls GetValue(). Check value.Kind == FormattedValueKind.Member to leave items untouched. A numbered placeholder is named after the member, or Item for an item of a collection or a dictionary value.

Empty collections​

Members that are often empty, e.g. the bonus tracks of an album, can be left out while they are empty:

await Expect.That(album).MatchesSnapshot().Ignoring.EmptyCollections();
Snapshot
Album {
  Title = "Let It Be",
  Tracks = [
    "Two of Us",
    "Dig a Pony"
  ]
}
  • .Ignoring.EmptyCollections() leaves out each member whose value is an empty array, list, set, dictionary or other collection that knows its count, here BonusTracks = [].
  • A null value and an empty string are kept, and so are empty items of a collection or values of a dictionary, which keep their place.
  • A sequence that does not know its count, like a LINQ query or an iterator, is kept as well and only enumerated once to be written, as it might only be enumerable once.

A string is compared as raw text and has no members, so a member or type rule on a string subject throws an InvalidOperationException.

For all snapshots​

Maskings that apply to every snapshot are set with Customize.aweXpect.Snapshots().Maskings, e.g. in an assembly-level setup, from the factories of SnapshotMasking in the namespace aweXpect.Snapshots. They have the same names and semantics as the maskings of an expectation:

Customize.aweXpect.Global.Snapshots().Maskings.Set([
    SnapshotMasking.Guids(),
    SnapshotMasking.Dates(),
    SnapshotMasking.MachineName(),
    SnapshotMasking.Regex(new Regex(@"localhost:\d+"), "localhost:<port>"),
]);

They are applied after the maskings of the expectation, in the order of the list, so a specific masking of the expectation goes before a general one for all snapshots. Members, types and lines are left out for all snapshots with Customize.aweXpect.Snapshots().Ignorings and the factories of SnapshotIgnoring, e.g. Ignorings.Set([SnapshotIgnoring.EmptyCollections(), SnapshotIgnoring.MemberOf<Album>(a => a.Price), SnapshotIgnoring.LinesContaining("Build date").IgnoringCase()]). Member and type rules for all snapshots are ignored for a string subject, and line rules for any other subject. Setting a value replaces the list; to extend an outer setting, e.g. for one async flow, include it:

using (Customize.aweXpect.Snapshots().Maskings.Set([
           .. Customize.aweXpect.Snapshots().Maskings.Get(),
           SnapshotMasking.Text(library.Owner, "<owner>"),
       ]))
{
    await Expect.That(playlist).MatchesSnapshot();
}

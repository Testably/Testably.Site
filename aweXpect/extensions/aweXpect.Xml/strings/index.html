XML strings

String comparison as XML​

You can verify that a string is equal to the expected XML, compared by its content instead of its formatting:

string order = """<order id="42"><item sku="A1" price="1.0"/></order>""";
string expected = """
                  <order id="42">
                    <item price="1.00" sku="A1" />
                  </order>
                  """;

await Expect.That(order).IsEqualTo(expected).AsXml();

As the price differs, the expectation fails with:

Failure message
Expected that order
is XML equivalent to <order id="42">
  <item price="1.00" sku="A1" />
</order>,
but it differed as /order/item/@price was "1.0" instead of "1.00"

Actual:
<order id="42"><item sku="A1" price="1.0"/></order>

Expected:
<order id="42">
  <item price="1.00" sku="A1" />
</order>

The documents are equivalent, when they only differ in

  • the order of the attributes,
  • the prefixes of namespaces, as elements and attributes are compared by their namespace and local name,
  • whitespace-only text between elements, unless xml:space="preserve" keeps it,
  • comments, processing instructions and the XML declaration,
  • CDATA sections instead of escaped text, or <a/> instead of <a></a>.

Texts and attribute values are compared exactly, including leading and trailing whitespace, and the order of the child elements is significant, unless you ignore the element order.

Each difference names the path of the node: every element by its local name, followed by its position among the siblings of the same name, if there are several, e.g. /order/item[2]/@price, and every text as text(). The child elements are paired by this path, so an additional element is reported as unexpected instead of shifting the elements after it, and a different order is reported once for their parent.

You can ignore members whose values change between runs, e.g. AsXml(o => o.IgnoringMember("@createdAt")).

If the subject is not valid XML, the expectation fails with the reason:

Failure message
Expected that order
is XML equivalent to <order id="42" />,
but it was "<order id=\"42\">", which could not be parsed as XML: Unexpected end of file has occurred. The following elements are not closed: order. Line 1, position 16.

Actual:
<order id="42">

Expected:
<order id="42" />

The expected string must be valid XML, otherwise an ArgumentException is thrown. Like for validation, a document type definition (DTD) is prohibited in both strings. As XML is compared by its content, AsXml() cannot be combined with IgnoringCase(), Using(comparer) or another match type like AsWildcard(), and it is not available on Contains or DoesNotContain for a string subject.

AsXml() is also available on other string comparisons, e.g. on the items of a collection or on the message of an exception:

await Expect.That(orders).All().AreEqualTo("""<order id="42" />""").AsXml();
await Expect.That(orders).Contains("""<order id="42" />""").AsXml();
await Expect.That(Act).Throws<InvalidOperationException>().WithMessage("""<error code="42" />""").AsXml();

Validation​

You can verify that a string is a well-formed XML document:

string track = """<track title="Let It Be" artist="The Beatles" />""";

await Expect.That(track).IsValidXml();

If the closing tag was missing, i.e. <track title="Let It Be" artist="The Beatles">, the expectation would fail with:

Failure message
Expected that track
is valid XML,
but it could not be parsed: Unexpected end of file has occurred. The following elements are not closed: track. Line 1, position 47.

This verifies that the string can be read to its end by an XmlReader without exceptions. The string must contain exactly one root element; a fragment like <a/><b/> or an empty string is not valid XML. The document is not validated against a schema, and an encoding in the XML declaration is not checked, as the string is already decoded.

For security reasons, a document with a document type definition (<!DOCTYPE ...>) is not valid XML: DTD processing is prohibited and external resources are never resolved, so that verifying untrusted input is not exposed to XML external entity (XXE) or entity expansion attacks:

Failure message
Expected that track
is valid XML,
but it contained a document type definition (DTD), which is prohibited for security reasons

You can add further expectations on the root XElement parsed from the subject:

string track = """<track title="Let It Be" artist="The Beatles" />""";

await Expect.That(track).IsValidXml().Which(root => root.Matches("""<track title="Let It Be" />"""));

The expectations are only verified when the string is valid XML. Like with XDocument.Parse, whitespace-only text between elements is dropped, unless xml:space="preserve" keeps it.

Or you can verify that the string is valid XML and matches an expected XML in one step:

string track = """<track title="Let It Be" artist="The Beatles" />""";

await Expect.That(track).IsValidXmlMatching("""<track title="Let It Be" />""");
await Expect.That(track).IsValidXmlMatchingExactly("""<track artist="The Beatles" title="Let It Be" />""");

IsValidXmlMatching("""<track title="Yesterday" />""") would fail with:

Failure message
Expected that track
is valid XML which matches <track title="Yesterday" />,
but it differed as /track/@title was "Let It Be" instead of "Yesterday"

You can also verify that a string is not valid XML:

string track = "Let It Be";

await Expect.That(track).DoesNotComplyWith(it => it.IsValidXml());

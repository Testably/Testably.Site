One test, three libraries

A service that exports a report to disk and notifies the team. No temp folder, no hand-written fake, no guessing what failed.

[Test]public async Task Export_WritesReportAndNotifiesTeam(){    MockFileSystem fileSystem = new();← Testably.Abstractions    INotifier notifier = INotifier.CreateMock();← Mockolate    ReportService sut = new(fileSystem, notifier);     await sut.ExportAsync("Q3");     await That(fileSystem).HasFile("reports/Q3.json");← aweXpect.Testably    await That(notifier.Mock.Verify.Send("Report Q3 exported")).Once();← aweXpect.Mockolate}

MockFileSystem behaves like the real one on Windows, Linux and macOS, all in memory.

CreateMock() is source-generated: a typo in a setup is a compile error.

HasFile(…) reads as a sentence and names the missing path when it fails.

aweXpect
Readable, AOT-ready assertions.

Every expectation is awaited, for values, tasks, streams and exceptions alike.

await That(message)
    .IsEqualTo("It's a compliment");
// but it was "It's a complement"

Mockolate
AOT-ready mocking for .NET.

Source-generated mocks, set up with regular method calls. No reflection, no proxies.

dispenser.Mock.Setup
    .Dispense("Dark", It.IsAny<int>())
    .Returns(true);

Automated migration

The Mockolate.Migration package contains a Roslyn analyzer and code fixes that migrate Moq and NSubstitute mocks to Mockolate. The analyzer reports every mock it can migrate, and the code fix rewrites the whole mock in one step: the construction, all its setups and verifications, the event wiring and, for Moq, every .Object access.

DiagnosticSource libraryCode fix title
MockolateM001MoqMigrate Moq to Mockolate
MockolateM002NSubstituteMigrate NSubstitute to Mockolate

Installation​

Install the package into the test project you want to migrate, next to Mockolate itself:

  • .NET CLI
  • PackageReference
  • Central Package Management
dotnet add package Mockolate.Migration
<PackageReference Include="Mockolate.Migration" Version="0.6.0" PrivateAssets="all" />
Directory.Packages.props
<PackageVersion Include="Mockolate.Migration" Version="0.6.0" />
Project file
<PackageReference Include="Mockolate.Migration" PrivateAssets="all" />

Latest version: 0.6.0

The package contains only the analyzer and the code fixes, no runtime code. You need it only while you migrate: once a project no longer uses Moq or NSubstitute, remove the reference again.

Migrate your tests​

After you install the package, each mock that can be migrated is reported as a warning (MockolateM001 or MockolateM002). Apply the code fix in your IDE (Visual Studio, Rider or VS Code with C# Dev Kit). To migrate many mocks at once, use Fix all occurrences for the document, project or solution, or run the code fix from the command line:

dotnet format analyzers --diagnostics MockolateM001 MockolateM002

Then build, run your tests and check the cases that need manual review.

What the code fix rewrites, with examples and the supported constructs, is described per source library:

  • Migrating from Moq
  • Migrating from NSubstitute

What needs manual review​

The code fix leaves a // TODO(MockolateM001) or // TODO(MockolateM002) comment where it cannot finish the migration on its own. Search for them after you apply the fix:

  • Nested mocks: Moq and NSubstitute create mocks for nested members (m => m.Child.Prop) automatically. Mockolate does not, so set up the parent to return a mock for Child yourself.
  • CallInfo callbacks that cannot be rewritten safely, for example when they use call directly, compute the index at runtime, assign out or ref arguments, call an ambiguous call.Arg<T>(), or declare local variables with the same names as the parameters of the method.

The code fix does not mark these cases:

  • Call order: the code fix removes Moq's InSequence(…) wrapper from the setups. Mockolate checks the order after the calls instead: add a Then(…) chain to the verification.
  • Constructs that are not in the tables of supported Moq and NSubstitute constructs, for example Moq's Verifiable(), VerifyAll(), Protected(), As<T>() or Mock.Of<T>(), and NSubstitute's Arg.Do<T>(…), Received.InOrder(…) or Configure(). Rewrite them by hand; the translation table shows the Mockolate equivalents.
